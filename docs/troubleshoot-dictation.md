# Troubleshoot a silent hotkey or missing pasted text on Mac

**Short answer:** Check the three macOS grants—Microphone, Input Monitoring, and Accessibility—then test the selected model and the focused text field separately. Input Monitoring lets OpenVoiceFlow detect the chosen push-to-talk key; Microphone lets it capture speech; Accessibility lets it synthesize ⌘V. A failure at one stage does not prove the others are broken. These instructions cover native [v0.6.6](https://github.com/shimoverse/openvoiceflow/releases/tag/native-v0.6.6), verified November 14, 2026 (Pacific time), not the legacy Python build.

## Before testing

Use macOS 14 or later and the native app. Complete onboarding with a downloaded local speech model while connected to the internet. Open a disposable text field, such as a new note, and make sure it has the insertion cursor; avoid passwords or sensitive content during diagnosis. In the app's Settings, note your chosen hotkey (default `fn`), selected speech engine, and whether **Paste automatically** is on. The [settings defaults in the released source](https://github.com/shimoverse/openvoiceflow/blob/f41879063e0ed8c8356dbba90c7dcb86d7844de9/native/Sources/OpenVoiceFlow/Settings.swift) and [model preparation flow](https://github.com/shimoverse/openvoiceflow/blob/f41879063e0ed8c8356dbba90c7dcb86d7844de9/native/Sources/OpenVoiceFlow/AppController.swift) show why a model must be ready before the first useful take.

## Find the failing stage

1. In **System Settings → Privacy & Security**, check **Microphone**, **Accessibility**, and **Input Monitoring** for OpenVoiceFlow. The app requests them during onboarding; macOS owns these grants, and revocation can affect an existing installation. Return to the app and retry after changing a grant. The [native permission implementation](https://github.com/shimoverse/openvoiceflow/blob/f41879063e0ed8c8356dbba90c7dcb86d7844de9/native/Sources/OpenVoiceFlow/Permissions.swift) checks all three separately.
2. Hold the *configured* hotkey, speak a full short sentence, then release. If no recording indication appears, first confirm the menu-bar app is running and not paused, the hotkey is the one you are pressing, and Input Monitoring is granted. If you changed the hotkey, test the new key rather than assuming `fn`. The app's [hotkey startup path](https://github.com/shimoverse/openvoiceflow/blob/f41879063e0ed8c8356dbba90c7dcb86d7844de9/native/Sources/OpenVoiceFlow/AppController.swift) can fail when the event tap cannot start.
3. If recording begins but the app reports **Microphone unavailable**, inspect the Microphone grant and the active mic in macOS. Try a normal-length take: a release that is too quick, a silent input, or an unprepared model can yield no useful transcript. If Settings shows a model-preparation error, reconnect, use **Try again**, and wait until that model is ready before an offline test.
4. If the transcript appears but not in your destination, focus a writable text field and ensure **Paste automatically** is on. If Accessibility was revoked, the released [paster](https://github.com/shimoverse/openvoiceflow/blob/f41879063e0ed8c8356dbba90c7dcb86d7844de9/native/Sources/OpenVoiceFlow/Paster.swift) leaves dictated text on the clipboard and the app prompts you to press **⌘V** manually. Try that immediately. This fallback is not a guarantee that every target application accepts synthetic paste.

## If it still fails

Test the same sentence in a second ordinary text editor to separate a target-app restriction from a capture problem. Revisit the app's model status and permission status rather than toggling unrelated cloud settings: AI cleanup is **Off** by default and is not required for dictation. If you file an [issue](https://github.com/shimoverse/openvoiceflow/issues), include macOS and app version, selected hotkey/model, the visible error, which of the four stages failed, and whether manual ⌘V worked; do **not** attach private recordings or transcripts. See the [offline verification checklist](verify-offline.md) once the online baseline works, or the [cleanup choices](choose-cleanup.md) if text arrives but its phrasing is not what you expected.
